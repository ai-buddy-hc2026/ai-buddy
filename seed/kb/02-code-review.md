# Code review в команде

## Зачем нужно ревью
Code review помогает найти ошибки до слияния, делиться знаниями о коде и держать единый стиль. Ревью проходит каждый pull request, который идёт в main.

## Как проходит ревью
1. Автор открывает pull request и назначает ревьюеров - обычно двух человек из команды.
2. Перед ревью автоматически запускаются линтеры и тесты. Если CI красный, ревьюеры PR не смотрят.
3. Ревьюер оставляет комментарии к строкам кода. Каждый комментарий - вопрос или предложение, а не приказ.
4. Автор отвечает на комментарии и вносит правки отдельными коммитами.
5. Когда все согласны, хотя бы один ревьюер ставит Approve, и автор делает merge.

## На что смотрят ревьюеры
Корректность логики, понятные имена, тесты на новое поведение, отсутствие секретов в коде, влияние на безопасность и права доступа.

## Сроки
Ревьюер старается ответить в течение одного рабочего дня. Если ответа нет, мягко напомни в командном чате.

## Советы стажёру
Делай небольшие PR. Пиши в описании, что и зачем изменено. Не принимай замечания на свой счёт: ревью проверяет код, а не человека. Стажёру полезно и самому ревьюить чужие PR - так быстрее учишься.
