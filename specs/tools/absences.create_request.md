# absences.create_request

Создание заявки на отсутствие в сервисе «Отсутствия» (мок). Действие с эффектом.

## Вход
| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| user_id | string | да | Только текущий пользователь |
| date | string (YYYY-MM-DD) | да | Дата отсутствия |
| type | enum | да | Один из типов из absences.get_policy |
| idempotency_key | string | да | Один ключ на одну заявку, повтор использует тот же ключ |

## Выход
```json
{"id": "ABS-1042", "status": "pending_approval", "approver": "lead_maria"}
```

## Права
Все роли, только за себя: `user_id` должен совпадать с токеном.

## Подтверждение
Обязательно. Агент не вызывает инструмент сам, а возвращает `action_proposal` с данными заявки. Вызов выполняет Go в `POST /actions/{id}/confirm` после нажатия «Отправить» и повторной проверки прав.

## Идемпотентность
Повтор с тем же ключом возвращает ту же заявку и не создаёт дубль. Это нужно для кнопки «Повторить» после сбоя.

## Ошибки
| Код | Когда |
|---|---|
| policy_denied | user_id не совпадает с токеном |
| invalid_date | неверный формат или дата в прошлом (HTTP 422) |
| invalid_type | тип вне списка (HTTP 422) |
| service_unavailable | сбой или таймаут мока, повторить с тем же ключом |

## События
`action_proposed`, `action_confirmed`, `action_failed`. Запись в `actions_log`.
