# checklist.get_plan

План адаптации пользователя: этапы, задачи, прогресс и следующий шаг.

## Вход
| Поле | Тип | Обязательно | Описание |
|---|---|---|---|
| user_id | string | да | Чей план. Для стажёра всегда он сам |

## Выход
```json
{
  "user_id": "intern_anya",
  "stage": {"id": 2, "title": "Неделя 2"},
  "progress": {"done": 6, "total": 14},
  "tasks": [
    {"id": "T-7", "title": "Открыть первый PR", "description": "...", "status": "todo",
     "deadline": "2026-11-13", "assignee": "intern", "kb_doc": "Первый pull request"}
  ],
  "next_step": {"task_id": "T-7", "title": "Открыть первый PR", "deadline": "2026-11-13"}
}
```
status: todo, in_progress, blocked, done.

## Права
- Стажёр: только свой план.
- Наставник: планы своих стажёров.
- Руководитель: в MVP не определено, по умолчанию отказ. Уточнить у Василия в policy-таблице.

## Ошибки
| Код | Когда |
|---|---|
| unauthorized | нет или просрочен токен |
| policy_denied | чужой план или роль без доступа (пишется событие policy_denied) |
| plan_not_found | у пользователя нет плана |

## Использование агентом
Ответ на «что мне делать дальше?» строится по `next_step` и `progress`. Данные также передаются в системный промпт.
