# Методика оценки эффекта MVP

Статус: методика расчёта, не отчёт о достигнутых результатах. Значения 40-48 и
55-65 часов ниже являются исходными допущениями; источник и применимость к когорте
нужно подтвердить до публикации численной экономии. HTTP /metrics/summary не реализован.
События приложения описаны в [events.md](events.md); они не измеряют автоматически
удовлетворённость, время наставника или повторные обращения вне приложения.

# Исходные данные и допущения

- Шестимесячная программа стажировки - 40-48 часов взаимодействия с наставником.
- Девятимесячная программа стажировки - 55-65 часов взаимодействия с наставником.

В процессе адаптации стажёр выполняет различные задачи: от настройки рабочего окружения и освоения инструментов разработки до выполнения первых самостоятельных задач, получения обратной связи и решения организационных вопросов, связанных с прохождением стажировки.

Основные категории обращений к наставнику:

- организационные вопросы;
- закреплённые задачи и особенностям их выполнения;
- используемые инструменты и технологии разработки;
- развитие профессиональных навыков;
- получение обратной связи и проведение рефлексии.

Категории, определяющие основные направления, в которых AI-ассистент может снизить количество обращений к наставнику.

Немаловажным является вопрос - какое обращение можно считать закрытым?
Закрытым обращением считается запрос, по которому стажёр получил точный и достаточный ответ, позволяющий самостоятельно решить возникший вопрос, без необходимости повторного обращения за дополнительными сведениями.

Если после получения ответа стажёр повторно обращается к наставнику или другому специалисту для уточнения информации по той же проблеме, такое обращение не считается закрытым.

# Экономия

Цель расчёта - определить, сколько рабочего времени наставников экономит ассистент за счёт самостоятельного закрытия обращений стажёров, а также повторного использования ответов из базы знаний S-6.

В качестве базового показателя используются затраты времени наставников без ассистента: **40-48 / 55-65 часов**.

## 1. Базовая нагрузка без использования ассистента

Для каждого типа обращения необходимо определить:

- `N_i` - количество обращений соответствующего типа за период;
- `T_i` - среднее время наставника на обработку одного обращения, в минутах.

Общая базовая нагрузка:

```
T_baseline = Σ(N_i × T_i) / 60
```

## 2. Нагрузка с использованием ассистента

Обращения разделяются на три категории:

- `N_resolved` - обращения, самостоятельно закрытые ассистентом без участия наставника;
- `N_review` - обращения, требующие проверки, исправления или уточнения ответа наставником;
- `N_escalated` - обращения, переданные наставнику из-за отсутствия информации в базе знаний или необходимости дополнительного решения.

Фактическая нагрузка наставника:

```
T_actual = (N_review × T_review + N_escalated × T_escalated) / 60
```

где:

- `T_review` - среднее время проверки или исправления ответа;
- `T_escalated` - среднее время обработки переданного наставнику обращения.

**Экономия времени наставника:**

```
T_saved = T_baseline - T_actual
```

**Доля сэкономленного времени:**

```
Saving_Rate = (T_saved / T_baseline) × 100%
```

Обращения, закрытые ассистентом самостоятельно, учитываются как полностью снятая нагрузка наставника. Ответы «не знаю» не считаются успешным закрытием: фактическое время последующей обработки обращения включается в `T_actual`.

## 3. Эффект повторного использования ответов(S-6)

Сценарий S-6 предполагает публикацию ответа на который не нашлось ответа в базу данных.
Для каждого опубликованного ответа необходимо учитывать:

- `N_reused` - количество последующих обращений, закрытых с использованием ответа;
- `T_mentor` - базовое время наставника на обработку аналогичного обращения;
- `T_publish` - время создания, проверки и публикации ответа.

**Экономия от повторного использования одного ответа**:

```
S6_saved = (N_reused × T_mentor - T_publish) / 60
```

**Экономия по когорте стажёров:**

```
S6_cohort = Σ(S6_saved_i)
```

**Накопленная экономия по всем когортам:**

```
S6_total = Σ(S6_cohort_i)
```

Первоначальные затраты на создание и публикацию ответа учитываются один раз. `Каждое последующее подтверждённое использование актуального ответа увеличивает накопительную экономию.`

## 4. Итоговая экономия

T_saved уже включает самостоятельно закрытые вопросы, в том числе ответы S-6. Поэтому S6_total используется как разрез общего эффекта и не прибавляется второй раз. Сумма T_saved + S6_total допустима только для непересекающихся наборов обращений с однократно учтёнными затратами публикации. Здесь T_baseline и T_actual уже выражены в часах.

```
T_total_saved = T_saved
```

## 5. Допущения и ограничения расчёта

1. Ответ формируется исключительно на основании найденных фрагментов базы знаний. При отсутствии релевантной информации запускается сценарий "Не знаю".
2. Проверка, исправление и уточнение ответов ассистента учитываются как затраты времени наставника.
3. Повторные обращения по одной проблеме объединяются по единому идентификатору вопроса.
4. Ответ S-6 учитывается как повторно использованный только при подтверждённом получении ответа стажёром.
5. Устаревшие или требующие повторной проверки ответы не считаются экономией времени.
6. Первоначальные затраты на создание ответа S-6 учитываются однократно.

## Данные для воспроизводимого отчёта

Для каждого расчёта указать период, когорту, источник данных, единицу измерения и
знаменатель. При нулевом знаменателе результат не определён, а не равен 0%.
DR требует идентификатора уникальной проблемы и проверки отсутствия повторного обращения;
такая связь с обращениями вне приложения пока не автоматизирована.
RAT измеряется от принятия запроса до сохранённого успеха действия и включает ожидание
подтверждения; время генерации ответа является отдельным показателем.
CCR использует выбранный набор задач и один момент/период наблюдения.
CSAT требует реальных оценок, MTS - сопоставимых замеров времени наставника.
Для повторных попыток одного действия используется один action_id; retry не становится
новым завершённым обращением. Демонстрационные числа нельзя выдавать за замеры.
