# MVP AI-buddy

## Назначение и статус

Выбранный командой объём решения. Основа: предоставленный `MVP.pdf`, четыре страницы, и обсуждённые уточнения протокола. Требования организаторов отдельно изложены в [выжимке кейса](requirements/case.md).

Это целевой объём, а не отчёт о готовности. Реализация в `main`, открытые PR и рабочие команды указаны в [README](../README.md). Схема БД и межсервисный контракт имеют собственные статусы согласования.

AI-buddy помогает стажёру в первые недели: слева панель «Мой онбординг», справа чат. Польза - уменьшить повторяющиеся обращения к наставнику и довести организационный запрос до сохранённого результата. Экономия времени не считается измеренной до проверки.

## Сценарии и приёмка

Пять продуктовых сценариев и одна сквозная проверка безопасности:

| ID | Сценарий | Считается готовым, если |
|----|----------|------------------------|
| S-1 | Панель онбординга | Видны этапы, задачи, прогресс и следующий шаг. Изменение статуса ощущается быстрее секунды и сохраняется после перезагрузки. Ошибка сохранения корректно отображается/откатывается. |
| S-2 | Ответ по базе знаний | Ответ появляется постепенно и содержит документ/раздел источника. При отсутствии ответа помощник признаёт это и предлагает обратиться к наставнику. |
| S-3 | Отгул через мок «Отсутствия» | До подтверждения заявки нет. После нажатия видны ID и статус результата, история сохраняется после перезагрузки. Повтор при сбое не создаёт дубль. Это главный сценарий демо. |
| S-SEC | Проверка прав | Все 10 подготовленных атак отклонены, чужие данные не показаны. Отказ выполняется в коде, а не только в промпте. |
| S-5 | Передача вопроса наставнику | Пользователь подтверждает передачу; назначенный наставник видит вопрос и разрешённый контекст переписки. |
| S-6 | Ответ наставника в KB | Наставник явно публикует ответ. После индексации другой стажёр с подходящими правами получает ответ с источником без повторного обращения к наставнику. |

Номера сохранены из командного MVP. Отсутствие S-4 не означает недостающую реализацию: сценарий доступов исключён из объёма.

## Обязательные правила

- Авторизация и проверка роли, владельца и команды выполняются в Go перед каждым инструментом. Аргументы агента не определяют права.
- Создание отгула и передача вопроса наставнику требуют явного подтверждения. Предложение действия и успешная генерация текста не означают выполнения.
- Повтор выполнения использует тот же ключ идемпотентности. ID результата и его корпоративный статус сохраняются.
- Источники берутся из доступной пользователю KB. При пустом поиске нельзя выдумывать регламент или ссылку.
- Материалы KB помечены «Тестовая инструкция, не регламент Авито».
- При отсутствии ключа LLM приложение запускается: панель и уже доступные действия работают, чат показывает «Ассистент временно недоступен».
- Перезагрузка браузера не удаляет задачи и историю. Обрыв SSE не должен автоматически запускать вторую генерацию.

## Границы сервисов

| Часть | Ответственность |
|-------|-----------------|
| Go API | Mock-login/JWT, роли intern/buddy/lead, policy-слой, внешний HTTP API, SSE, сохранение данных, подтверждение и выполнение действий через MCP. |
| Python AI-service | Агент, LLM, RAG и эмбеддинги, вызов разрешённых MCP-инструментов через Go, события в Redis. FastAPI выбран командой. |
| Frontend | React + TypeScript, TanStack Router/Query, Zustand, Zod; интерфейс стажёра и наставника, подтверждения и состояния ошибок. |
| PostgreSQL + pgvector | Прикладная история, тестовые данные, KB и чанки, предложения/результаты действий, события и флаги. |
| Redis | Транспорт событий и временные данные по контракту. Не заменяет постоянную историю. |

Контракт `docs/ai-contract.md` находится в [PR Макса #60](https://github.com/ai-buddy-hc2026/ai-buddy/pull/60/files), схема `docs/db.md` в [PR #62](https://github.com/ai-buddy-hc2026/ai-buddy/pull/62/files). После слияния используйте файлы в репозитории и обновите ссылки. Не создавайте вторые копии контрактов.

HTTP-схемы Go и схемы MCP согласуются отдельно. Ниже указан целевой состав, а не реализованные endpoint.

## Целевые операции

Внешний Go API:

- `POST /auth/mock-login`, `GET /me`.
- `GET /onboarding/plan`, `PATCH /tasks/{id}`.
- `POST /chat/messages`, `GET /chat/stream/{id}`.
- `POST /actions/{id}/confirm`, `GET /actions`.
- `GET /buddy/interns`, `POST /buddy/escalations/{id}/answer`.
- `GET /metrics/summary`.

MCP-набор: `checklist.get_plan`, `checklist.update_status`, `knowledge.search`, `employees.get_manager`, `absences.get_policy`, `absences.create_request`, `absences.list_for_employee`, `escalation.create`.

Стажёру доступны свой план и разрешённые задачи; наставнику планы назначенных стажёров; руководителю данные своей команды в пределах инструмента. Создание отсутствия выполняется только за себя. KB фильтруется по разрешённым данным. Точная матрица прав фиксируется в спецификациях инструментов.

## Данные и качество

- Тестовые логины: `intern_anya`, `buddy_ilya`, `lead_maria`; для проверки границ нужен стажёр другой команды, например `intern_petr`. Это логины, не обязательный формат PK.
- Чек-лист покрывает неделю 1, неделю 2 и недели 3-4. Задачи, ответственные и дедлайны фиксируются в seed/документе чек-листа; текущая работа находится в [PR #61](https://github.com/ai-buddy-hc2026/ai-buddy/pull/61/files).
- Готовятся 30 вопросов: 20 с ответом в KB, 10 без ответа, и 10 атак на права. До появления отчётов это план проверки, не достигнутый результат.
- Нужны SDD, тесты сценариев и воспроизводимое покрытие более 80% строк. Общая команда покрытия не считается существующей, пока не добавлена.

Метрики: вопросы, закрытые без наставника, ответы с источниками, выполненные действия, эскалации, отказы по правам и прогресс чек-листа. Формулы и правила исключения повторов согласуются с аналитиком. Демо-значения не выдаются за измеренный эффект.

## Демо на 3-5 минут

1. Войти как `intern_anya`, показать этап, прогресс и следующий шаг, изменить статус задачи.
2. Спросить «что мне делать дальше?» и вопрос про code review; показать постепенный ответ, источник и тестовую пометку.
3. Попросить отгул, проверить карточку, подтвердить отправку, показать ID/статус в истории.
4. Включить сбой мока и повторить операцию; показать отсутствие дубля и сохранение результата после перезагрузки.
5. Запросить чужие отсутствия; показать отказ без чужих данных и событие `policy_denied`.
6. Спросить о теме без ответа и подтвердить передачу наставнику.
7. Войти как `buddy_ilya`, ответить и явно добавить ответ в KB. После индексации повторить вопрос от другого разрешённого стажёра.
8. Показать метрики, пояснить, какие данные тестовые.

## Что не входит в MVP

- Настоящий SSO, реальные HR-интеграции и реальные данные сотрудников.
- Зарплаты, выплаты, медицинские данные и другие чувствительные операции.
- Отдельные интерфейсы руководителя и HR.
- Выдача доступов S-4, Kafka, несколько агентов и викторины.

Изменение объёма сначала согласуется с командой и отражается здесь. В README и презентации заявляется только работающая функциональность.

## Готовность к сдаче

Необходимо подтвердить запуск из чистой копии с примером env и тестовыми данными, прохождение сценариев, инструкции и версии зависимостей, настройки модели без секретов, тестовые учётные записи, SDD, тесты и покрытие. Нужны видео и PDF-презентация со ссылками.

Сроки проверяются по актуальным объявлениям организаторов. Внутренние даты заморозки фич и тега из исходных командных документов не служат новому чату автоматическим разрешением создавать тег, прекращать работу или отправлять решение.
