# Личные уведомления

Уведомления принадлежат AI-buddy: они сообщают о действиях и ответах внутри приложения.
Отдельный корпоративный mock для их хранения не нужен. Источники календаря остаются
за интерфейсом CalendarStore; данные уведомлений и настройки находятся в PostgreSQL.
Ветка зависит от реализации [коллег (PR #105)](https://github.com/ai-buddy-hc2026/ai-buddy/pull/105)
и [календаря (PR #106)](https://github.com/ai-buddy-hc2026/ai-buddy/pull/106).

## События и получатели

| Тип | Когда создаётся | Получатели |
|-----|----------------|------------|
| booking_confirmed | Подтверждена новая бронь | Гость и принимающий коллега с активным логином. |
| meeting_reminder | За 30 минут до встречи | Те же участники, если разрешены напоминания. |
| mentor_answer | Наставник впервые ответил или изменил текст ответа | Стажёр, задавший вопрос. |

Для коллеги без логина уведомление не создаётся. Повтор подтверждения, повтор ответа
и публикация неизменённого ответа в KB не создают дубли. Запись уведомлений входит
в транзакцию брони или ответа: невозможно сохранить действие и потерять уведомление
при сбое между двумя записями. Новая редакция текста ответа создаёт новое уведомление;
при открытии показывается актуальный ответ, а не историческая редакция.

Полный путь создания эскалации S-5 ещё не подключён к Python. Уведомление об ответе
работает для существующих эскалаций; это не завершает S-5.

## Напоминания и рабочие часы

Сервер проверяет очередь при запуске и каждые 30 секунд. Несколько экземпляров Go
могут работать одновременно: блокировки и уникальный ключ получателя исключают
повторную доставку. Перезапуск не теряет очередь, Redis и SSE для неё не нужны.
На запуске восстанавливаются отсутствующие напоминания будущих броней, старые
подтверждения не рассылаются. При ошибке восстановление повторяется.

Настройки по умолчанию: напоминания включены, понедельник-пятница, 10:00-19:00.
Часовой пояс берётся из users.timezone, затем teams.timezone. Его изменение этим API
не предусмотрено. Начало рабочего интервала включено, конец исключён; ночной интервал
и пустая неделя не допускаются. Используются IANA-пояса и локальные календарные дни.

Вне рабочих часов напоминание переносится на ближайшее рабочее время только если
оно раньше начала встречи. Иначе оно становится expired. После начала встречи
напоминание недоступно даже до следующего прохода worker. При бронировании
за 30 минут до начала или позже остаётся подтверждение, отдельного напоминания нет.
Отключение подавляет ожидающие напоминания. Повторное включение не возвращает
подавленные уведомления; новые брони следуют новым настройкам. Подтверждения и ответы
не отключаются и видны сразу. Рабочие часы ограничивают напоминания, а не список фактов.

Режим «Не мой день» и существующие переключатели дополнительных активностей остаются
без изменений. Уведомления не читают этот режим и не меняют его. Связь с ним отложена
до решения продакта; серверного поля mode и endpoint для него в этой задаче нет.

## HTTP и права

Все маршруты требуют JWT, актуального активного пользователя и команды. Ответы
возвращаются с Cache-Control: no-store. Пользователь и команда определяются в Go,
поля recipient_id, user_id, team_id и mode из браузера не принимаются.

| Метод и путь | Контракт |
|-------------|----------|
| GET /notifications | items, next_cursor, unread_count. limit 1-100, по умолчанию 20; cursor подписан и связан с пользователем, командой и limit. |
| PATCH /notifications/{id}/read | Пустое тело; устанавливает read_at один раз, повтор возвращает ту же дату. |
| GET /notifications/{id}/resource | Разрешённая бронь или текущий ответ наставника; повторная проверка владельца и команды. |
| GET /me/settings | preferences.meeting_reminders, work_days (1=пн, 7=вс), work_start, work_end, timezone, version. |
| PATCH /me/settings | Полный набор изменяемых полей из GET без timezone. Все поля обязательны; version защищает от перезаписи изменений из другой вкладки. |

Чужой или недоступный объект возвращает 404. Ошибки формата - 400, отсутствие JWT -
401, запрет policy - 403, устаревшая версия - 409 VERSION_CONFLICT, ошибка БД - 503.
Настройки существующего пользователя создаёт db-init без перезаписи. Для новой записи
без user_settings GET возвращает defaults с version=0; первый PATCH создаёт version=1.
Списки не раскрывают тему чужой встречи или чужой ответ. Ссылки на источники типизированы;
произвольные URL из данных не используются. Бронь можно открыть и после завершения
встречи через постоянное подтверждение, независимо от 14-дневного окна календаря.

## Интерфейс и проверка

В API-режиме колокольчик доступен всем ролям, показывает число непрочитанных и список
с пагинацией. Опрос выполняется раз в 30 секунд в активной вкладке и при возврате фокуса.
Открытие деталей отдельно отмечает уведомление прочитанным. При ошибке есть повтор,
подмена серверных данных локальными отсутствует. Кеш запросов разделён по пользователю;
после выхода старые команды записи блокируются. Браузерные push, email и внешние
мессенджеры не подключены. Демо-режим без API сохраняет прежний интерфейс.

Карточка настроек сохраняется явной кнопкой. При 409 введённые значения остаются,
актуальные настройки загружаются отдельной кнопкой. Из localStorage старые значения
не переносятся: они не были привязаны к пользователю.

Проверки: Go unit/HTTP; интеграция с TEST_DATABASE_URL (отдельная тестовая БД) проверяет
транзакционный откат, параллельные worker, права, курсоры, повторное чтение, рабочие
часы, отключение, backfill и повтор db-init. Frontend Vitest проверяет транспорт и
смену сессии; Playwright с Go проверяет бронь, получателей, чтение, версии и настройки
после перезагрузки. Команды запуска - в README сервисов.
